# План тестирования — Sourdough

Дата: 2026-06-01

Приложение для домашних пекарей: трекер закваски, рецепты, сообщество.
Перед релизом нужно пройти все проверки приоритетов 1 и 2. Приоритет 3 — после релиза.

---

## Ресурсы и производительность

### Сколько пользователей выдержит
- SQLite — однопоточная БД, потолок ~50-100 одновременных пользователей
- Для 10-20 зарегистрированных — более чем достаточно (активных одновременно 2-5)
- Узкое место: загрузка фото (диск) и Gemini API (внешний лимит)

### Место на сервере (10-20 пользователей)

| Что | Расчёт | Объём |
|-----|--------|-------|
| БД (SQLite) | 20 польз × 100 кормлений × ~1KB | ~2-5 MB |
| Фото кормлений | 20 польз × 50 фото × ~2MB | ~2 GB |
| Фото рецептов | 20 польз × 10 рецептов × 3 фото × ~2MB | ~1.2 GB |
| Приложение + зависимости | Next.js build | ~300 MB |
| **Итого** | | **~3.5-4 GB** |

> Рекомендация: 10 GB свободного места с запасом. Стоит добавить сжатие фото при загрузке (уменьшит объём в 3-5 раз).

### Найденные проблемы (нужно исправить до релиза)
1. Нет проверки типа файла при загрузке — можно загрузить любой файл
2. Нет ограничения размера файла — один запрос может забить диск
3. Фото доступны без авторизации — `public/uploads/` раздаётся напрямую
4. Нет rate-limiting — можно бесконечно пробовать пароли
5. Path traversal — `starterId` в upload не проверяется на спецсимволы (`../`)

## Приоритет 1 — Критичное (блокирует релиз)

### Безопасность

> Для проверок S5-S7 нужно два аккаунта. Для S4 — curl или Postman.

#### Загрузка файлов
- [ ] S1. Загрузить `.html` файл с `<script>alert('XSS')</script>` как фото кормления → открыть URL в браузере. Не должен выполниться скрипт
- [ ] S2. Загрузить файл 500MB+ → должен быть отказ с понятной ошибкой
- [ ] S3. Скопировать URL фото кормления, открыть в другом браузере без логина → фото НЕ должно быть доступно
- [ ] S10. Отправить upload с `starterId=../../etc` → не должно создать файлы за пределами папки uploads

#### Доступ к чужим данным
- [ ] S5. Подставить чужой ID закваски в GET/DELETE `/api/starters/[id]` → ошибка 403/404
- [ ] S6. Отправить PUT/DELETE `/api/feedings` с ID чужого кормления → ошибка 403/404
- [ ] S7. Отправить PUT/DELETE `/api/recipes` с ID чужого рецепта → ошибка 403/404

#### XSS (внедрение кода)
- [ ] S8. Написать комментарий `<script>alert(1)</script>` → отображается как текст, не выполняется
- [ ] S9. Зарегистрироваться с именем `<img src=x onerror=alert(1)>` → на странице сообщества отображается как текст

#### Перебор паролей
- [ ] S4. Отправить 50+ запросов POST на `/api/auth/login` с разными паролями → после N попыток должна быть блокировка или задержка
